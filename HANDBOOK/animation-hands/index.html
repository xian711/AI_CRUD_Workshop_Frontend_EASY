文字版速查

這一支是手把手版（跟著做）：只講點哪裡、貼哪一段、看到什麼就對了。想知道為什麼這樣做，看講課版。建議左邊開動畫、右邊開 VS Code，看完一段就暫停、自己做一次。

動畫裡的畫面，都是 2026-10-04～11 在 Windows 11 實際操作時拍下來的：VS Code（繁體中文介面）、Claude Code 擴充、PowerShell 終端機、Chrome。大字版終端機裡的每一行，也都是同一次操作印出來的真實文字。

配音由 Google Gemini 3.8 Flash TTS 預先錄好：阿哲帶你一步一步操作，小芸講檢查點和卡住時怎麼辦。聲音全部是預錄好的 mp3 檔，播放時不用連 AI、不花 token，也不用瀏覽器內建的語音。動畫裡的指令只放在畫面字卡，完整指令看下面和手冊。

名詞：SDD＝規格驅動開發（先文件，再程式；程式改了，文件跟著改）。文件有三份：SRS（這一版答應了什麼）、設計文件 DESIGN（怎麼做）、圖 DIAGRAMS（用瀏覽器開，看圖不用看程式）。

Step 3 用 SDD 叫 AI 做新模組

  • 複製範本（檔案總管）：VS Code 左邊對 sample-app 按右鍵 →「在檔案總管中顯示」→ 按兩下進去 → Ctrl+A 全選 → 按住 Ctrl 點掉 node_modules、.nuxt（有 .output 也點掉）→ Ctrl+C
  • 按左上角的向上箭頭「↑」三次 → 進 step3_new_module → Ctrl+Shift+N 新增資料夾 my-equipment-app → 點進去 Ctrl+V
  • 回到 step3_new_module，按住 Ctrl 選三份文件：PRD、技術約定、最小樣板 → 複製 → 貼進 my-equipment-app（會用終端機的，手冊 ⓪ 有一段指令，效果一樣）
  • 「檔案」→「開啟資料夾」→ my-equipment-app → 終端機 pnpm install
  • PRD 是白話寫的：沒有英文欄位名、沒有選擇題。技術約定是給 AI 的，你不用讀
  • 右下角「✻ Claude Code」→ 模型選 Opus 5.5、effort High、核准模式 Auto → 貼手冊 ② 的起手 prompt（4 行）→ 送出
  • AI 自己找 PRD 的缺口出選擇題。照手冊 ③ 的課堂拍板表選（編碼 PW-GEN-001 要選 Other 自己打）；表上沒有的選「建議」
  • AI 交 SRS、DESIGN、DIAGRAMS、TASKS 四個檔。圖用瀏覽器開（在 my-equipment-app 的終端機）：start DIAGRAMS-中心裝備物資.html，每張圖看「怎麼看」和「看完你要答得出來」
  • 說「開工」之前，把模型切成 Sonnet 5.5
  • 驗收：pnpm dev --port 3101，開 http://localhost:3101/equipment/crud。有小落差就附畫面：Win+Shift+S 框起來 → 輸入框 Ctrl+V → 一句話講「看到什麼、期望什麼」，一次講一件

AI 沒問就寫程式：貼手冊的救援 prompt 叫它停

Step 4 讓 AI 修到全綠、分身挑錯

  • 用瀏覽器開報告（教材根目錄）：start step3_new_module\my-equipment-app\loop\LOOP-REPORT.html
  • 測試報告：start step4_loop_e2e\e2e\playwright-report\index.html
  • 「檔案」→「開啟資料夾」→ 回到教材根目錄
  • 開新的 Claude Code 對話（模型 Sonnet 5.5），貼手冊的 LOOP prompt（4 行；鐵律和產出都寫在 step4_loop_e2e/LOOP-規矩.md）
  • AI 自己啟動受測 App，3100 被占就自己換埠；跑 run-e2e 修到 7 條全綠；再開一個 Opus 5.5 的子代理，用 Playwright 開瀏覽器截圖做對抗審查
  • 修好的每一條，報告都放「修改前」「修改後」兩張圖
  • 要動到共用檔的，AI 停下來用選擇題問你。選擇題框裡放不了圖：先看報告「要你裁決的事」每一題附的畫面，再回答。建議的不一定要選，寫著「會動到共用元件」的，想清楚影響範圍
  • 測試本身的問題它只列出來，不會自己改；寫著「講測試」的題目找講師
  • 看三份東西：my-equipment-app/loop/LOOP-REPORT.html（給人看的報告，結論在最前面）、step4_loop_e2e/e2e/playwright-report/index.html（測試報告）、SRS／DESIGN／DIAGRAMS 有沒有標「step4 LOOP 後」。loop/LOOP-LOG.md 是流水帳，你的裁決也記在裡面，有紅燈時再翻

鐵律：修兩次不好就停；不准改測試、不准放寬標準；審的模型要比寫的高一級

用 macOS／Linux 的對照

動畫只拍 Windows。macOS 的步驟一樣，只有指令不同（都在手冊 HANDBOOK.html 裡）：

  • 前置檢查：bash preflight.sh（Windows 是 .\preflight.ps1）
  • 開網頁：open HANDBOOK/HANDBOOK.html（Windows 是 start）
  • 複製範本：用 Finder 照樣複製（不要帶 node_modules、.nuxt、.output），或手冊的 rsync -a --exclude node_modules --exclude .nuxt --exclude .output …（Windows 是檔案總管或 robocopy）
  • E2E：bash step4_loop_e2e/run-e2e.sh（Windows 是 run-e2e.ps1）；換埠用 PORT=3101（Windows 是 $env:PORT='3101'）

卡住時

  • 一執行 .\preflight.ps1 就出現「已停用指令碼執行」或「未經數位簽署」：先執行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned，再重跑。公司電腦不准改這個設定時，找 IT 或講師。
  • 截圖貼不進 Claude Code：macOS 用 Shift+Cmd+Ctrl+4 框起來（直接存到剪貼簿），再到輸入框 Cmd+V。
  • preflight 出現 [FAIL]：照修復提示做 → 關掉終端機重開再跑 → 還是紅，整段輸出（連 [PASS] 的行）貼給 AI。
  • 網頁一打開就是 500、寫著 useColorMode is not defined：舊的建置快取被複製過來了。在跑 pnpm dev 的終端機按 Ctrl+C 停掉，刪掉該專案的 .nuxt、.output 兩個資料夾再 pnpm dev。
  • pnpm 噴一大串紅字：從你打的指令那一行開始整段複製，貼給 AI；同一個錯誤修兩次還不行，找講師。
  • 網址打不開：多半是網頁伺服器沒在跑。到要看的專案資料夾（範本是 sample-app、新模組是 my-equipment-app）執行 pnpm dev，看終端機印出的網址和埠號，那個終端機不要關。
  • pnpm dev 說 3100 被占用：不用關掉別的程式，Nuxt 會自己換一個埠（例如 3101）印在終端機；LOOP 的 AI 也會自己換埠。
  • AI 要開 Chrome 或其他工具問你同不同意：這門課用不到，選「No」，跟它說「不用開瀏覽器，繼續」。

檔案位置

這支動畫在教材的「HANDBOOK\animation-hands」資料夾裡，檔名是 index.html（用瀏覽器打開）。

改字幕或重拍用的原始檔，在「HANDBOOK\animation-hands\_src」資料夾裡：講稿 script_hands.py（字幕和配音都從這裡來）、場景檔 scenes-hands.js、配音腳本 make_hands_audio.py、截圖腳本、座標檔 meta.json。
