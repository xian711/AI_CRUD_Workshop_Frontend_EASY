文字版速查

動畫裡的畫面，都是 2026-10-04 在 Windows 11 實際操作時拍下來的：VS Code（繁體中文介面）、Claude Code 擴充、PowerShell 終端機、Chrome。大字版終端機裡的每一行，也都是同一次操作印出來的真實文字。

Step 0 準備環境

  • VS Code 選單「終端機」→「新增終端」（快捷鍵 Ctrl+`）
  • cd D:\
  • git clone https://github.com/xian711/AI_CRUD_Workshop_Frontend_EASY.git
  • 「檔案」→「開啟資料夾」→ 選 AI_CRUD_Workshop_Frontend_EASY → 信任作者
  • cd step0_course_intro，再 .\preflight.ps1

看到「前置檢查全數通過，可以開課！」就過關

Step 2 玩範本

  • 先回到教材根目錄：cd ..（開頭要是 PS D:\AI_CRUD_Workshop_Frontend_EASY>）
  • cd step2_speedrun_kit/2.1_sample_app/sample-app
  • pnpm install → pnpm dev（這個終端機不要關）
  • 按住 Ctrl 點 http://localhost:3100/
  • 五個檢查點：新增、編輯、刪除確認、篩選＋網址、匯出 CSV
  • 要再打指令：終端機右上角「＋」開第二個

共用的 3 個核心檔不要動；四份規矩在 sample-app 最上層

Step 3 叫 AI 做新模組

  • 教材根目錄整段貼上手冊 step3 ⓪ 的複製指令，出現 >> 後再按 Enter
  • 「檔案」→「開啟資料夾」→ my-equipment-app
  • 右下角「✻ Claude Code」→ 貼起手 prompt → 送出
  • 三題選擇題照課堂拍板：D1 補刪除＋確認視窗、D2 做 CSV 匯出、D3 簡化版編碼（不加機關前綴、同一個編碼不累加數量）
  • 確認任務清單 → 開工
  • 驗收前先確認網頁有在跑：打不開就在 step3_new_module\my-equipment-app 執行 pnpm dev
  • 驗收：http://localhost:3100/equipment/crud

AI 沒問就寫程式：貼手冊的救援 prompt 叫它停

Step 4 讓 AI 修到全綠

  • 「檔案」→「開啟資料夾」→ 回到教材根目錄
  • 開新的 Claude Code 對話，貼手冊的 LOOP prompt
  • 等它交報告：7 passed
  • 抽查一：在 step4_loop_e2e 跑 git diff e2e/，應該是空的。它只看得到還沒交給 git 的修改；要百分之百確定（或拿到的是 zip 副本），用 Get-FileHash 跟講師發的雜湊比對
  • 對抗審查：App 的問題交回 AI 修；測試本身的問題不叫 AI 改，交給講師裁決
  • 抽查二：在 my-equipment-app 搜尋 useTemplateListPage，應該找得到；一行都找不到，就請 AI 說明共用零件是不是被拆掉、另寫了一套

鐵律：修兩次不好就停；不准改測試、不准放寬標準

用 macOS／Linux 的對照

動畫只拍 Windows。macOS 的步驟一樣，只有指令不同（都在手冊 HANDBOOK.html 裡）：

  • 前置檢查：bash preflight.sh（Windows 是 .\preflight.ps1）
  • 開網頁：open HANDBOOK/HANDBOOK.html（Windows 是 start）
  • 複製範本：rsync -a --exclude node_modules --exclude .nuxt --exclude .output …（Windows 是 robocopy）
  • E2E：bash step4_loop_e2e/run-e2e.sh（Windows 是 run-e2e.ps1）
  • 抽查共用件：grep -n useTemplateListPage pages/equipment/crud/index.vue（Windows 是 Select-String）

卡住時

  • 一執行 .\preflight.ps1 就出現「已停用指令碼執行」或「未經數位簽署」：先執行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned，再重跑。公司電腦不准改這個設定時，找 IT 或講師。
  • preflight 出現 [FAIL]：照修復提示做 → 關掉終端機重開再跑 → 還是紅，整段輸出（連 [PASS] 的行）貼給 AI。
  • 網頁一打開就是 500、寫著 useColorMode is not defined：這次實拍在全新下載的參考解上也遇到過，重開一次就好。在跑 pnpm dev 的終端機按 Ctrl+C 停掉，再打一次 pnpm dev；還不行，刪掉該專案的 .nuxt、.output 兩個資料夾再跑。
  • pnpm 噴一大串紅字：從你打的指令那一行開始整段複製，貼給 AI；同一個錯誤修兩次還不行，找講師。
  • localhost:3100 打不開：多半是網頁伺服器沒在跑。到要看的專案資料夾（範本是 sample-app、新模組是 my-equipment-app）執行 pnpm dev，那個終端機不要關。
  • localhost:3100 開到別的網站，或 pnpm dev 說 3100 被占用：別的程式先占了 3100，先關掉它（preflight 會檢查這一項）。
