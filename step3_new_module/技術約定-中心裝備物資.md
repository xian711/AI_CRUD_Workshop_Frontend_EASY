# 技術約定 — 中心裝備物資（資訊單位提供）

> **給 AI 讀。業務單位不用寫，也不用看。**
>
> 1. `PRD-中心裝備物資.md` 是業務單位用白話寫的「要什麼」。
> 2. 這份是資訊單位（IT）跟後端講好的「接起來要長什麼樣」：網址、欄位英文名、示範資料、測試掛點。
> 3. 兩份衝突，或這份沒講到的事，用選擇題問人，不要自己決定。

## 2. 欄位英文名

**欄位英文名就是未來後端 API 的介面，定了就不改。** 後端課會照這張表做資料庫。

| PRD 的名字 | 欄位英文名 | 型別 |
|---|---|---|
| （系統用） | `id` | 文字：系統流水號，例 `E-001`。網址用它，跟品項編碼分開 |
| 分類 | `categoryKey` | 文字：分類代碼（第 3 節） |
| 項目 | `name` | 文字 |
| 品項編碼 | `code` | 文字：系統產生 |
| 數量 | `qty` | 整數，0 以上 |
| 單位 | `unit` | 文字 |
| 規格說明 | `spec1` | 文字 |
| 保管人 | `keeper` | 文字 |
| 保管人電話 | `keeperPhone` | 文字 |
| 存放地點 | `locationName` | 文字 |
| 狀態 | `status` | 代碼：`normal`＝正常、`maintenance`＝維修中、`scrapped`＝已報廢 |
| 採購日期 | `purchaseDate` | 文字 `YYYY-MM-DD`，沒填是空字串 |
| 備註 | `specNote` | 文字 |

釐清時如果要加欄或拆欄（例如保管人電話拆成手機、市話兩欄），選擇題裡要寫明：「這會跟技術約定不一樣，後端也要跟著改」。

## 4. 示範資料（mock）

還沒有後端，資料先放在前端記憶體。重新整理網頁，就回到示範資料。

| 約定 | 值 | 為什麼要定死 |
|---|---|---|
| 筆數 | **24 筆** | 一頁 20 筆，要超過 20 筆才看得到分頁 |
| 分類 | **10 個分類，每個至少 1 筆** | 分類篩選和排序才驗得到 |
| 狀態 | **正常、維修中、已報廢都要有** | 綠、黃、紅三種顏色才驗得到 |
| 同品名 | **至少一個品名有 2 筆以上** | 用品名找「有縮小、但不只剩 1 筆」才驗得到 |
| 編碼 | **每一筆都不重複** | 編碼是唯一能找到某一筆的欄位，測試靠它追蹤新增、修改、刪除 |

參考解的分佈（不用一模一樣）：資通訊 5、供電 3、事務 3、個人防護 3、儲物 2、收容 2、緊急物資 2、醫療 2、清消 1、其他 1；「筆記型電腦」和「發電機」各 2 筆。

## 5. 測試掛點（step4 的自動測試會用）

1. **表單每一欄的外框**要有 `data-field="欄位英文名"`，錯誤紅字放在這個外框裡。範本的欄位元件已經有，照範本複製改名就有。
   - 品項編碼也是表單的一欄：`data-field="code"`，裡面是**唯讀的輸入框**（標題旁邊要不要再顯示一次，隨你）。
   - 規格說明、備註用**多行文字框**（`<textarea>`）。
   - 桌機表格的前兩欄：**第 1 欄分類、第 2 欄項目（品名）**；品項編碼可以放在項目那一格的第二行。
2. 下面 4 個地方沒有好認的文字可以找，所以掛 `data-testid`：

| `data-testid` | 掛在哪 |
|---|---|
| `equipment-keyword` | 關鍵字搜尋框的外框 |
| `equipment-total` | 顯示總筆數的元素 |
| `equipment-row` | 桌機表格的每一列 `<tr>` |
| `equipment-code` | 資料列裡的品項編碼 |

3. 按鈕上的字要看得出動作，要包含這幾個詞：新增、儲存、編輯、刪除、取消、清除（清除關鍵字）。測試用「包含這個詞」找按鈕，不綁全名。
4. 驗證失敗時，右下角提示要寫「請修正 N 個欄位」（harness 的 `design-system-summary.md` 已經規定）。

沒掛 `data-testid` 不會直接死當，測試有退路（第一個輸入框、「共 N 筆」字樣、`table tbody tr`）。但掛上最穩。

---

## 6. 測試驗什麼、不驗什麼

1. step4 的 7 條自動測試，只驗 PRD、這份約定，和你在釐清時拍板的事。
2. **不驗畫面用字**：按鈕寫「新增品項」或「新增裝備」、成功提示寫什麼，都可以。
3. **不驗編碼格式**：編碼怎麼編是釐清時你拍板的。測試只驗兩件事：選好分類和項目後馬上算得出來、同一份清冊裡不重複。
4. 測試紅了，先分兩種：
   - **功能沒做到** → 修 App。
   - **測試在驗 PRD 和約定都沒寫的東西** → 停下來寫進 LOOP 報告，那是規格問題，交給人裁決。
