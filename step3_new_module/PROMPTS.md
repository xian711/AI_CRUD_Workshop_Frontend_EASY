# Step 3｜Prompt 包（複製即用）

這一頁的 prompt 都可以整段複製貼上。用 **Agent 模式**跟 AI 對話（它需要能自己讀檔、改檔）。

順序：先貼【起手 prompt】→ AI 出選擇題你回答 → AI 出任務清單你確認 → 開發中用【修正 prompt】→ 最後貼【收工 prompt】。

> **前提**：先完成 README 的 [3.0 準備工作區](README.md)，把範本複製成 `my-equipment-app` 並在該資料夾開 Agent——Agent 工作目錄＝`my-equipment-app` 專案根目錄，以下 prompt 提到的檔案都在這個根目錄。

---

## 【起手 prompt】

> 複製下面整段貼給 AI。這一段最重要，它同時交代了「先讀什麼、先別做什麼、要怎麼問」。

```
你是本專案的前端工程師。我們要用現成的 CRUD 標準範本，開發一個新模組「中心裝備物資」。

請先「依序」讀完以下文件（以下皆在專案根目錄），讀完再動作：
1. CLAUDE.md（專案憲法，所有規則的入口）
2. CODE-RULES-ui-本專案.md（前端規則：色碼、命名、行數、驗證等鐵律）
3. 使用說明-複製範本開發新模組.md（複製範本的標準工作流程與八檔心法）
4. PRD-中心裝備物資.md（本模組的真實需求，共 26 欄，是從現有系統逆向整理的）
5. SCOPE-課堂範圍決策.md（課堂已裁決的範圍：核心 12 欄＋補刪除等六題參考答案）

【重要】讀完後「先不要寫任何程式」。PRD 是完整現況，兩小時的課堂做不完，也有些地方（例如刪除功能、匯出、進階篩選）需要我裁決。

所以請你先做一件事：**以「選擇題」的形式，向我提出範圍釐清問題。**
- 每題 2 到 4 個選項；
- 每題標出你「建議的選項」並附一句理由；
- 聚焦在「這堂 2 小時 CRUD 課該做多少」，例如：欄位做幾個、PRD 沒有的刪除功能要不要補、借用／維保／匯入這些非 CRUD 功能要不要做、匯出做不做、編碼規則簡化到什麼程度、存放地點要不要做級聯地址。

等我逐題回答後，你再輸出一份「任務清單」（用 T1、T2… 編號，8 到 10 個任務），然後停下來等我確認，我說「開工」你才開始。

開發時全程遵守 harness 規則（CLAUDE.md 與 CODE-RULES）：禁止硬編碼色碼與 px、禁止 console.log、日期欄用原生 date input、下拉用「全部」哨兵、單檔行數控制在規範內。

每完成一個任務，回報「一行」進度（例如「T3 完成：列表頁欄位與篩選已改為裝備物資」），不要一次把所有程式碼倒出來。
```

> **講師版：不放 SCOPE 讓 AI 自己問。** 若要讓學員親自體驗「釐清」的過程，複製工作區時就別放 `SCOPE-課堂範圍決策.md`，起手 prompt 也拿掉第 5 點——AI 讀完 PRD 後會自己用選擇題來問範圍，你再拿 SCOPE 當對答案的參考解。

---

## 【釐清階段】AI 會問你什麼

貼完起手 prompt，AI 應該回你一組選擇題，長得像這樣（實際六題與參考答案見 `SCOPE-課堂範圍決策.md`）：

```
Q1. 欄位要做多少？
  (a) 全部 26 欄
  (b) 核心 12 欄  ← 建議：兼顧完整與可完成
  (c) 只做 5 欄
```

你可以直接回「Q1 選 b、Q2 選 b、Q3 選 b…」，或照 SCOPE 的裁決一次回覆。

### 如果 AI 沒問就直接動工，怎麼辦？

有時 AI 太積極，跳過提問直接開始寫。看到它在建檔改檔，立刻打斷，貼這段救援 prompt：

```
停，先不要寫程式，也先不要建任何檔案。

請先以「選擇題」的方式向我確認範圍，每題 2 到 4 個選項並標出你的建議選項。至少涵蓋：欄位數量、要不要補刪除功能、借用／維保／匯入這些非 CRUD 功能做不做、匯出做不做、編碼規則簡化程度、存放地點要不要級聯地址。

我逐題回答後，你再列任務清單、等我確認才開工。
```

## 【任務清單範例】

你確認範圍後，AI 應該產出類似下面的清單。這是「參考長相」，不必一字一樣，但顆粒度應該接近——**每個任務都小到可以單獨驗收**：

```
T1  資料模型與 mock 種子：定義 EquipmentItem 型別、10 分類列舉、24 筆種子資料（涵蓋三種狀態）
T2  複製改名五檔：index.vue / [id].vue / useEquipmentItems.ts / EquipmentFormField / EquipmentStatusBadge
T3  列表頁：改表格欄位、關鍵字＋分類＋狀態篩選、排序、分頁、URL 同步
T4  表單頁：改 12 欄輸入元件與必填驗證（電話有填才驗、採購日不晚於今天）
T5  連動下拉與編碼產生：分類→項目連動、選定後自動推算品項編碼（簡化版）
T6  刪除功能：列表垃圾桶 + AppConfirmModal 二次確認
T7  CSV 匯出：全量匯出、含 BOM、欄位對應 12 欄
T8  文件補齊：撰寫 SRS 與 SDD（SDD 記下「正式版建議改軟刪除」待辦）
T9  自行走一輪 CRUD 驗證：新增→編輯→刪除→篩選→匯出 逐項自測回報
```

看到清單後，若順序或內容合理就回「開工」；覺得少了什麼（例如漏了狀態標籤顏色）就先補一句再放行。

## 【修正 prompt 範本】

驗收發現問題時，用「看到 / 期望 / 只改這個」的三段結構。一次只提一個問題。

**句型一｜顯示不對**

```
我在【列表頁的採購日期欄】看到【顯示成 2026/7/1】，
我期望【顯示成 2026-07-01（補零、用連字號）】。
請只改這一個問題，其他不要動。
```

**句型二｜行為不對**

```
我在【新增頁】操作時看到【分類還沒選，項目下拉就已經可以點】，
我期望【一定要先選分類，項目下拉才啟用，而且只出現該分類的項目】。
請只改這一個問題，改完告訴我動了哪個檔。
```

**句型三｜兩次修不好，重新描述**

```
這個問題我們來回兩次還是不對，先停。
我重新描述一次：現況是【刪除按下去直接就刪掉，沒有跳確認框】；
我要的是【按垃圾桶後先跳一個確認彈窗，按「確認刪除」才真的刪，按取消則不動】；
專案已有現成的 AppConfirmModal，請直接用它，不要自己另做一個。
```

## 【收工 prompt】

全部任務做完、你也驗收過後，讓 AI 自己對規則做最後一次體檢：

```
開發完成。請你對照 CODE-RULES 自我檢查並回報結果，逐項列出通過或未過：
1. 有沒有硬編碼色碼（hex）或硬編碼 px？色與間距是否一律走 token？
2. 有沒有殘留 console.log 或註解掉的死碼？
3. 每個檔案的行數是否在規範內？有沒有哪個檔過長該拆？
4. 有沒有殘留範本的舊字串（Template、template/crud、人員）？請 grep 掃過。
5. 日期欄是否用原生 date input、下拉是否用「全部」哨兵？
6. mock 資料的欄位名是否已當成未來接後端的 interface（不再隨意改名）？

有未過的項目，列出檔名與行號，並提出修正建議，等我確認再改。
```
