# Step 3｜Prompt 包（複製即用）

用 **Agent 模式**（AI 要能自己讀檔、改檔）。前提：已完成 README 的 3.0，Agent 工作目錄＝`my-equipment-app` 專案根目錄。

順序：【起手 prompt】→ AI 問三題你拍板 → AI 列任務你確認 → 開發中用【修正 prompt】→ 最後【收工 prompt】。

---

## 【起手 prompt】

```
你是本專案的前端工程師。我們要用現成的 CRUD 標準範本，開發新模組「中心裝備物資」。

請先「依序」讀完專案根目錄的四份文件，讀完再動作：
1. CLAUDE.md（專案憲法）
2. CODE-RULES-ui-本專案.md（前端鐵律：色碼、命名、行數、驗證）
3. 使用說明-複製範本開發新模組.md（複製範本的標準流程與八檔心法）
4. PRD-中心裝備物資.md（課堂版需求：12 欄，內含第 5 節「三個待決策點」）

讀完後「先不要寫任何程式」。針對 PRD 第 5 節的三個待決策點（D1 刪除、D2 匯出、D3 編碼規則），
用「選擇題」逐題問我：每題 2 到 4 個選項，標出你建議的選項並附一句理由。

我逐題拍板後，你再輸出任務清單（T1、T2… 約 8 個，每個小到可單獨驗收），
停下來等我確認，我說「開工」你才開始。

開發時全程遵守 harness 規則：禁止硬編碼色碼與 px、禁止 console.log、
日期欄用原生 date input、下拉用「全部」哨兵、單檔行數控制在規範內。
每完成一個任務回報「一行」進度，不要把程式碼整段倒出來。
```

## 【救援 prompt】——AI 沒問就直接動工時

```
停，先不要寫程式、不要建任何檔案。
請先針對 PRD 第 5 節的三個待決策點，用選擇題逐題問我（每題 2-4 個選項＋你的建議）。
我拍板後你再列任務清單，等我確認才開工。
```

---

## 【任務清單參考長相】

不必一字一樣，但顆粒度要接近——每個任務都小到可以單獨驗收：

```
T1  資料模型與 mock 種子：EquipmentItem 12 欄型別、10 分類查表、24 筆種子（三種狀態都有）
T2  複製改名五檔：index.vue / [id].vue / useEquipmentItems.ts / FormField / StatusBadge
T3  列表頁：欄位、關鍵字＋分類＋狀態篩選、排序、分頁、URL 同步
T4  表單頁：12 欄輸入與驗證（電話有填才驗、採購日不晚於今天）
T5  連動下拉與編碼產生：分類→項目連動、自動編碼（簡化版）
T6  刪除＋CSV 匯出（依 D1、D2 拍板結果）
T7  文件：SRS 與 SDD（記下「正式版建議改軟刪除」待辦）
T8  自測一輪：新增→編輯→刪除→篩選→匯出，逐項回報
```

順序合理就回「開工」；覺得少了什麼（例如狀態標籤配色）先補一句再放行。

---

## 【修正 prompt 範本】

「看到 / 期望 / 只改這個」三段式，一次只提一個問題：

```
我在【列表頁的採購日期欄】看到【顯示成 2026/7/1】，
我期望【顯示成 2026-07-01】。
請只改這一個問題，其他不要動。
```

兩次修不好就重新描述（換個說法、給乾淨起點），並指名現成零件：

```
這個問題我們來回兩次還是不對，先停。我重新描述：
現況是【刪除按下去直接刪掉，沒有確認框】；
我要的是【按垃圾桶先跳確認彈窗，按「刪除」才真的刪】；
專案已有現成的 AppConfirmModal，請直接用它，不要自己另做一個。
```

---

## 【收工 prompt】

```
開發完成。請對照 CODE-RULES 自我檢查並逐項回報通過／未過：
1. 有沒有硬編碼色碼（hex）或 px？色與間距是否一律走 token？
2. 有沒有殘留 console.log 或死碼？
3. 各檔行數是否在規範內？
4. 新模組的檔案內有沒有殘留範本舊字串（Template、template/crud、人員）？grep 掃過再回答。
5. mock 欄位名是否已當成未來 API 介面（不再隨意改名）？
有未過的，列出檔名與行號＋修正建議，等我確認再改。
```

> **第 4 點的合理保留（不算違規）**：共用檔的 import（`useTemplateListPage`、`templateValidation`、`templateCsv` 本來就帶 template 字樣）；`/template/crud` 範本正本路由（留著當回歸對照）；「複製自 XXX」的出處註解。要清的是新模組檔案內忘了改的型別名、變數名、路由字串、UI 文案。
