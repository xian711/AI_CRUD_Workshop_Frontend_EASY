# PRD — 中心裝備物資（課堂版）

> **題目背景**：本模組取材自真實災防協作平台的「中心裝備物資」頁面。原系統有 26 個欄位，
> 還帶著借用歸還、維保提醒、照片上傳、匯入 Excel……原汁原味的 PRD 在課堂上絕對做不完。
> 所以這份已經先濃縮成「一堂課做得完」的課堂版——但**刻意留了三個決策點**（第 5 節）給你拍板，
> 這是你在這一步要練的事：**先釐清、再動工**。

---

## 1. 模組是什麼

供**鄉鎮公所協作中心**盤點與維護裝備物資清冊：品項、規格、數量、保管人、存放地點、狀態。

| 項目 | 說明 |
|------|------|
| 使用者 | 中心的裝備物資管理人員 |
| 資料 | 前端 mock（24 筆種子資料），尚未接後端 |
| 重要約定 | **mock 的欄位名＝未來接後端 API 的介面**，現在定好就不再改 |

## 2.1 種子資料與 E2E 掛載點（step4 會用到，先講明白）

> **為什麼這一節要存在？** 試教時兩位學員都做出「完全符合 PRD」的模組，卻在 step4 被 E2E 判紅——
> 因為那套測試依賴的東西（種子資料長什麼樣、畫面上哪個元素是總筆數）PRD 從頭到尾沒寫。
> **規格藏在測試裡就不是規格。** 所以把它們搬到這裡，明著講。

### 2.1.1 種子資料（mock fixture）

| 約定 | 值 | 為什麼要定死 |
|---|---|---|
| 種子筆數 | **24 筆** | E2E 用「動態讀總筆數」當基準，但列表要驗分頁，至少要 > 20 筆 |
| 涵蓋分類 | **10 個分類全部至少 1 筆** | 分類篩選與「分類→項目」排序才驗得到 |
| 涵蓋狀態 | **正常／維修中／已報廢三種都要出現** | 狀態標籤的綠／黃／紅才驗得到 |
| 重複品名 | **至少有一個品名出現 2 筆以上** | 關鍵字搜尋「有縮小但不只剩 1 筆」才驗得到；也逼出「同品名不同編碼」的情境 |
| 品項編碼 | **每一筆都不重複** | 編碼是列表裡唯一能定位單筆的欄位，E2E 靠它追蹤刪除／編輯的結果 |

參考解的實際分佈（你不必一模一樣，符合上面五條就好）：
ICT 5、POWER 3、OFFICE 3、PPE 3、STORAGE 2、SHELTER_SUPPLY 2、EMFOOD 2、MEDICAL 2、DECON 1、OTHER 1；
其中「筆記型電腦」與「發電機」各 2 筆。

> **不需要跟參考解逐字相同。** E2E v2 已經改成動態讀取筆數，不再寫死「24 筆」「發電機剛好 2 台」。

### 2.1.2 E2E 掛載點（4 個 `data-testid`）

自動化測試要在畫面上定位元素。能用語意（按鈕的可及名稱、`role`、可見文字）就用語意；
**下面這 4 個真的沒有語意可用，所以約定用 `data-testid`**：

| `data-testid` | 掛在哪 | 為什麼需要 |
|---|---|---|
| `equipment-keyword` | 關鍵字搜尋框的外框元素 | 頁面上不只一個輸入框，靠 placeholder 文字定位會綁死你的文案 |
| `equipment-total` | 顯示總筆數的那個元素 | 「共 N 筆」只是參考解的寫法，你想寫「總計 N 項」也可以 |
| `equipment-row` | 桌機表格的每一列 `<tr>` | 手機卡片與表格列同時存在，要分得出來 |
| `equipment-code` | 資料列裡的品項編碼 | 編碼跟品名同一格，靠「第幾個 div」定位一改版就碎 |

> 沒掛也不會直接死當——E2E 有語意退路（第一個 textbox、`共 N 筆` 正則、`table tbody tr`、該格最後一行）。
> 但掛上去最穩，而且只要 4 個屬性。

## 4. 功能需求

### 列表（Read）

- 桌機表格／手機卡片，資訊等價；預設每頁 **20** 筆、顯示總筆數；預設「分類→項目」升冪（分類依定義順序，非中文筆劃）。
- 關鍵字搜尋：比對「項目名稱＋品項編碼」，不分大小寫、部分比對。
- 分類、狀態下拉篩選（含「全部」）；點表頭切換升降冪；分頁每頁 10／20／50。
- 篩選與頁碼寫入 URL，重新整理不丟。
- 無符合條件時顯示空狀態提示。

### 新增（Create）

- 選定「分類＋項目」後即時顯示自動編碼（唯讀）。
- 按「儲存」時驗證：欄位下方紅字＋聚焦第一個錯誤欄位＋toast「請修正 N 個欄位」，不離頁。

### 編輯（Update)

- 表單預帶原值；「儲存」寫回並返回列表、「取消」不變更。

### 刪除（Delete）

- **待決策**（見 D1）。

### 狀態標籤

- 正常＝綠、維修中＝黃、已報廢＝紅。

## 5. 三個待決策點（課堂上由你拍板）

原系統就長這樣，PRD 照實記錄、不替你決定。AI 讀完會用「選擇題」問你這三題：

| # | 問題 | 背景 |
|---|------|------|
| D1 | 原系統的品項**沒有刪除功能**，要補嗎？ | 真實缺口照實保留。CRUD 教學少了 D 就不完整；範本有現成的確認彈窗元件 |
| D2 | 匯出在原系統是 **TODO 空實作**，做不做？ | 範本有現成 CSV 匯出工具，成本趨近零 |
| D3 | 品項編碼照原系統全套，還是簡化？ | 原系統：`{類別2碼}-{項目3碼}-{機關3碼+流水3碼}`，且同編碼會**累加數量**而非新增一筆。<br>**選「簡化」的話，格式由你定**（`PW-GEN-003`、`PW-003`、`EQ-0003` 都行），只要滿足兩條：**選定分類＋項目後能即時算出來**、**同一份清冊裡不重複**。<br>參考解用的是 `{類別2碼}-{項目3碼}-{流水3碼}`。step4 的 E2E **不驗格式、只驗這兩條**，所以你拍板成什麼都過得了。 |

---

> **給要跑 step4 E2E 的人的補充：**
> 這份 PRD 規定的是**功能與資料**，加上第 2.1 節那份「種子資料約定 ＋ 4 個 `data-testid` 掛載點」。
> 除此之外的 **UI 用字你自己決定**——按鈕要寫「新增品項」還是「新增裝備物資」、成功提示要寫「已新增品項」還是「已新增」、
> 搜尋框的 placeholder 要寫什麼，PRD 都不管，**step4 的 E2E v2 也已經改成模糊比對，不會再因為用字不同判你紅**。
>
> 所以照 PRD 做完，step4 的 7 條原則上就過得了。真的紅了，第一件事還是分辨兩種紅：
> **(1) 功能沒做到** → 修 App。**(2) 測試在驗 PRD 沒寫的東西** → 停下來寫進 LOOP 報告，那是規格問題不是你的問題。

## 6. 驗收條件

1. 進 `/equipment/crud`：桌機表格、預設每頁 20 筆、「分類→項目」升冪、正確顯示總筆數。
2. 先選「分類」→「項目」才可選，且只出現該分類的項目；清空分類時項目一併清空。
3. 關鍵字打品名或編碼片段能過濾（不分大小寫、部分比對）。
4. 點表頭「數量」可切換升降冪，排序後回到第 1 頁。
5. 新增頁選定「分類＋項目」後，標題區即時顯示自動編碼；必填未填按儲存出現紅字並聚焦，不離頁。
6. 新增／編輯後返回列表立即生效；狀態標籤配色正確。
7. 保管人電話填錯格式被擋；採購日期選未來日期被擋。
8. （若 D1、D2 拍板要做）刪除經二次確認才生效；CSV 匯出全量、含 BOM、中文不亂碼。
