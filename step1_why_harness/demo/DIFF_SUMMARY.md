# 純文字版差異摘要（no-harness vs with-harness）

> **這份是給「打不開瀏覽器」的人看的。**
> 正常上課請雙擊 `no-harness.html` 與 `with-harness.html`，兩個視窗並排看畫面——
> 那才是 step1 的原始體驗。但如果你在終端機裡、或是叫 AI Agent 幫你讀教材，
> 那兩份各三百到七百行的 HTML 原始碼會把重點淹掉。這份就是把重點先撈出來。
>
> 試教時兩位學員都回報「看不到畫面，這一步的教學效果掉七成」。這份補的就是那七成裡撈得回來的部分。
>
> ⚠️ **這份不能取代看畫面。** 顏色好不好看、間距舒不舒服、操作順不順手，文字寫不出來。
> 它能取代的只有「哪個決定是誰做的」這件事——而那正好是 step1 真正要你看的東西。

---

## 一句話版本

**兩份都能新增、都能刪除，畫面都不醜。差別是：左邊每個決定都是 AI 當場自己拿主意，右邊每個決定都查得到出處。**

---

## 1. 顏色從哪來

| | 沒 harness | 有 harness |
|---|---|---|
| token 命名 | AI 自己發明：`--brand`、`--brand-dark`、`--bg`、`--card`、`--text`、`--muted`、`--border`、`--danger`、`--danger-dark` | 照給定的規則：`--ui-sys-color-primary`、`--ui-sys-color-primary-hover`、`--ui-sys-color-error`、`--ui-sys-color-on-surface`… |
| 主色 | `#e8590c`（AI 自己挑的警示橘） | `#C8232C`（規則裡指定的品牌紅） |
| 品牌紅 `#C8232C` 出現次數 | **0 次** | 出現在 `--ui-sys-color-primary` |
| `:root` 之外的裸色碼 | **5 處**（`#fff` × 3、`#fbf7f2`、`#fde8e6`），共 3 個不重複色值 | **0 處** |
| `:root` 內的色碼 | 9 行宣告 | 12 行宣告、11 個不重複色值（`on-primary` 與 `surface` 都是 `#FFFFFF`） |

**看點**：左邊那套其實是「對的實務」——它知道要用 token、也真的建了一套。問題是那是**它的**一套。
兩套 token 合不起來，擺在你們現有系統旁邊就是兩個產品。

---

## 2. 業務規則從哪來

| | 沒 harness | 有 harness |
|---|---|---|
| 電話驗證 | 正規式 `/^[0-9+\-\s()]{6,15}$/`——6～15 個字元，數字、`+`、`-`、空白、括號都收 | 具名常數 `PHONE_PATTERN = /^09\d{8}$/`——只收台灣手機 09 開頭 10 碼 |
| `(02) 1234-5678` 會不會過 | **會過**（長度 14、字元全在允許集內） | **會被擋** |
| 血型選項 | A／B／AB／O／**不明**（5 個，多一個是 AI 自己加的） | 由具名常數 `BLOOD_TYPES = ['A','B','AB','O']` 動態產生（4 個） |
| 必填標記 | **沒有星號**，三個 `<label>` 就是「姓名」「電話」「血型」 | 每個必填欄位都有 `<span class="required-mark">*</span>`（共 4 處），紅色 |
| 錯誤訊息位置 | 沒有欄位級錯誤容器 | 每欄一個 `id="xxx-error"`，用 `aria-describedby` 關聯到輸入框 |

**看點**：顏色錯了肉眼看得出來；**驗證規則錯了，要等資料髒掉才會發現**。
左邊那個「不明」血型，就是三個月後有人問「為什麼統計對不起來」的起點。

## 3. 多出來的東西（harness 管不到的部分）

| 需求裡**沒有**要求的功能 | 沒 harness | 有 harness |
|---|:---:|:---:|
| `localStorage` 存檔 | ✅ 自己加了 | ✅ 自己加了 |
| 刪除確認 | ✅ 用瀏覽器原生 `confirm()` | ✅ 自製 modal（規則有要求二次確認） |
| 空清單提示 | ✖ | ✅ `#empty-state` |
| Esc 關閉彈窗 | ✖ | ✅ 監聽 `Escape` |
| 關掉彈窗後焦點歸還 | ✖ | ✅ 記 `lastFocusedElement` 再 `focus()` |
| `aria-live` 動態播報 | ✖ | ✅ |
| 響應式（手機寬度） | ✅ `@media (max-width: 640px)` | ✅ `@media (max-width: 640px)` |
| 表格欄位 | `#`／姓名／電話／血型／操作（多一個流水號欄） | 姓名／電話／血型（＋操作鈕） |

**看點**：**兩邊都自己多做了事，而且有 harness 那邊還多做更多。**
這就是 step1 最容易被忽略的一句話——**harness 管得住「怎麼寫」，管不住「做多少」**。
範圍要靠 PRD 和決策點管，那是 step3 的事。

## 4. 規模對照（給你一個量感）

| | 沒 harness | 有 harness |
|---|---:|---:|
| 檔案行數 | 312 行 | 751 行 |
| 表單 id 命名 | `volForm`、`name`、`phone`、`blood`（簡寫、隨手取） | `volunteer-form`、`name-input`、`phone-input`、`blood-type-select`（完整、可預期） |
| `<th>` 是否有 `scope` | 沒有 | 有 `scope="col"` |

行數多一倍不是因為「有 harness 比較囉嗦」，是因為它多做了無障礙、欄位級錯誤、自製彈窗這些規則要求的東西。

## 6. 這份摘要沒辦法告訴你的事

- **哪一版比較好看。** 兩版都不醜，左邊那版甚至可能更討喜（它自己配了色、加了圖示）。
- **操作起來的手感。** 按鈕大小、動畫、間距節奏。
- **視覺一致性。** 「像不像同一個團隊做的」這件事，只有把兩張畫面擺在一起才看得出來。

這三件事**只能靠人眼**。所以如果你手邊有瀏覽器，還是請打開那兩個 HTML 檔並排看一次——
這份摘要的用途是「看完畫面之後，用來對照證據」，不是「代替你看畫面」。
