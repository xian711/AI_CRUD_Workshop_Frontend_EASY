## 1. 目的與定位

本模組**不是業務功能**，而是一份「可執行的開發標準」：

1. **教育訓練教材**：新進人員透過一個完整、乾淨、可跑的 CRUD 範例，學會本專案的標準做法。
2. **新模組開發起點**：開發新 CRUD 模組時，複製本範本改名即可獲得符合規範的骨架。
3. **重構對照組**：與現行 roster 頁（單檔 2,255 行、三頁重複邏輯）對照，示範 Clean Code / Refactoring 原則的實際效益。

### 1.1 設計原則（約束所有 FR）

- **簡化**：示範實體僅保留具教學代表性的欄位型態（文字、enum、日期、陣列、巢狀地址、狀態）。
- **一致**：排序、分頁、確認對話框等一律採用專案內「最成熟的一種做法」，消除現況多套並存。
- **可複製**：所有範本檔案以 `Template` / `template` 命名空間隔離，複製改名即成新模組。
- **後端就緒**：資料層 API 一律非同步（Promise），未來以 `useFetch` 替換內部實作即可，呼叫端不變。

## 2. 示範實體：人員（TemplateMember）

自 roster 的 `RosterRecord`（約 40 欄）精簡為 17 欄，欄位命名與 roster 對齊以利日後整合：

| 欄位 | 型別 | 必填 | 教學代表性 |
|------|------|:---:|------|
| id | string（`M-001`） | 系統 | 主鍵 |
| name | string | ✅ | 一般文字 |
| gender | `'男' \| '女'` | ✅ | enum（radio/select） |
| birthDate | string（YYYY-MM-DD） | ✅ | 日期選擇 |
| idType | `'身分證' \| '居留證' \| '護照'` | ✅ | 相依 enum |
| nationalId | string | ✅ | 格式驗證（依 idType） |
| phone | string | ✅ | 格式驗證（09xxxxxxxx） |
| email | string | — | 格式驗證 |
| residenceCounty / residenceTownship | string | ✅ | 相依下拉（縣市→鄉鎮區） |
| residenceAddress | string | ✅ | 一般文字 |
| groupName | string（編組） | ✅ | select |
| positionCode | `'director' \| 'deputy' \| 'leader' \| 'member'` | ✅ | enum + 排序權重 |
| positionTitle | string（主任/副主任/組長/組員） | 系統 | 由 code 導出 |
| qualifications | string[]（防災士/TCERT/急救證照…） | — | 多值標籤 |
| status | `'在職' \| '停用'` | ✅ | 狀態 badge |
| note | string | — | 長文字 |
| updatedAt | string（YYYY-MM-DD） | 系統 | 稽核欄位 |

種子資料：**24 筆可讀的字面量資料**（非 hash 產生器），涵蓋所有編組、職務、狀態組合，分頁預設 10 筆/頁時恰有 3 頁。

## 3. Use Cases

| ID | 名稱 | 主要流程摘要 |
|----|------|------|
| UC-T-01 | 查詢瀏覽人員清單 | 進入列表 → 關鍵字/條件篩選 → 排序 → 分頁瀏覽；條件同步於 URL，可分享/重整還原 |
| UC-T-02 | 檢視人員明細 | 列表點列 → 整頁檢視（唯讀）→ 返回列表（還原查詢狀態） |
| UC-T-03 | 新增人員 | 列表按「新增」→ 整頁表單 → 欄位級驗證 → 儲存 → 返回列表並提示成功 |
| UC-T-04 | 編輯人員 | 檢視頁或列表按「編輯」→ 表單載入既有值 → 驗證 → 儲存 → 返回 |
| UC-T-05 | 刪除人員 | 列表操作「刪除」→ 二次確認對話框 → 刪除 → 提示成功 |
| UC-T-06 | 匯出 CSV | 列表按「匯出」→ 下載目前篩選+排序結果之 CSV（UTF-8 BOM） |

## 4. 功能需求（FR-T）

### 4.1 列表查詢（FR-T-10x）

- **FR-T-101** 篩選卡提供：關鍵字（比對姓名/電話/Email）、編組下拉、狀態下拉。
- **FR-T-102** 進階篩選（可折疊）：資格下拉、居住縣市/鄉鎮區相依下拉；折疊鈕顯示已啟用的進階條件數徽章。
- **FR-T-103** 提供「清除」重設所有條件並回到第 1 頁。
- **FR-T-104** 條件變更即時過濾（前端記憶體資料），並將頁碼重設為 1。
- **FR-T-105** 無符合資料時顯示空狀態（圖示 + 說明文字），不顯示空表格。

### 4.2 排序與分頁（FR-T-20x）

- **FR-T-201** 可排序欄位：姓名、編組、職務（依權重非筆劃）、狀態、更新日期。點表頭單欄排序，再點切換升降。
- **FR-T-202** 預設排序：職務權重升冪（主任在前）→ 姓名。
- **FR-T-203** 分頁預設 10 筆/頁，可切換 10/20/50/100；顯示「第 x 至 y 項，共 n 筆」。

### 4.3 檢視 / 新增 / 編輯（FR-T-30x）

- **FR-T-301** 檢視/新增/編輯共用一個整頁路由 `/template/crud/[id]`：`new` = 新增、`?mode=edit` = 編輯、其餘 = 檢視。
- **FR-T-302** 表單依區塊分組：基本資料、聯絡資訊、編組職務、其他。
- **FR-T-303** 欄位級驗證：必填 + 格式（電話/Email/證號依 idType），錯誤訊息顯示於**欄位下方紅字**，儲存時聚焦第一個錯誤欄位；不得只用 toast 帶過。
- **FR-T-304** 主要動作（儲存/取消/編輯/返回）一律 Teleport 至 `#breadcrumb-actions`（左側返回鈕用 `#breadcrumb-actions-left`），頁面內容區不重複渲染主要動作按鈕。
- **FR-T-305** 儲存成功 → toast 提示 → 返回列表並還原查詢狀態；取消 → 直接返回不儲存。

### 4.4 刪除（FR-T-40x）

- **FR-T-401** 刪除入口位於列表列操作區；點擊開啟 `AppConfirmModal`（danger variant），內文含人員姓名。
- **FR-T-402** 確認後刪除並 toast 提示；若當頁因刪除變空，自動退回前一頁。

### 4.5 匯出（FR-T-50x）

- **FR-T-501** 匯出目前**篩選 + 排序後**的完整結果（非僅當頁），CSV 含 UTF-8 BOM，檔名含日期。

### 4.6 URL 狀態同步（FR-T-60x）

- **FR-T-601** 篩選、排序、頁碼、每頁筆數同步至 URL query（僅寫入非預設值），重整/分享可還原。
- **FR-T-602** 前往明細頁攜帶 `return` query 保存列表狀態，返回時還原。

## 5. 業務規則（BR-T）

| ID | 規則 |
|----|------|
| BR-T-01 | 必填欄位見第 2 章「必填」欄；Email 選填但填了就必須符合格式 |
| BR-T-02 | 證號格式依 idType：身分證 `^[A-Z][12]\d{8}$`；居留證/護照僅檢查非空與長度上限 |
| BR-T-03 | 行動電話格式 `^09\d{8}$` |
| BR-T-04 | 刪除必須二次確認，確認文案需含該筆資料的識別資訊（姓名） |
| BR-T-05 | positionTitle 由 positionCode 導出，不可獨立編輯 |
| BR-T-06 | updatedAt 由系統於新增/編輯時寫入，表單不顯示為可編輯欄位 |

## 6. 非功能需求（NFR-T）

- **NFR-T-01 RWD**：`md` 以上顯示表格，以下顯示卡片清單；兩者資訊等價。
- **NFR-T-02 無障礙**：互動元件皆有 focus-visible ring；icon 按鈕有 aria-label；錯誤訊息以 `aria-describedby` 關聯欄位。
- **NFR-T-03 視覺**：全面使用 design token（COMP→SYS→REF），禁止硬編碼色值；模組屬「平時」類別 → 白/淡色底。
- **NFR-T-04 程式品質**：單檔 ≤ 500 行；無 magic literal（抽為具名常數）；無 console.log 殘留；無死碼。
- **NFR-T-05 效能**：衍生資料一律 `computed`；列表渲染不得在 template 內執行 O(n) 掃描函式。
