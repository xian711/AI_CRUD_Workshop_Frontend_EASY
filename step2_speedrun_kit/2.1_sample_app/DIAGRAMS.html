UML 圖面 — CRUD 標準範本（人員管理）

CRUD 是「新增、查詢、修改、刪除」四件事的英文縮寫。這個範本用「人員」當例子，把四件事做成一個標準模組。

不用看程式，看這 7 張圖就懂。對應文件（同資料夾）：SPEC-範例-人員CRUD.md（需求規格）、DESIGN-CRUD標準範本-v1.1.md（設計文件）｜ 畫面網址：/template/crud

③ 資料圖：一筆人員記哪些資料

這張圖在說什麼：一筆人員記 17 項資料，哪些一定要填、哪些有固定選項；旁邊是管理這些資料的幫手。

怎麼看
  • 每個框是一樣東西：框的最上面是名稱，下面每一行是它記的一項資料，或它會做的一件事。
  • 「新增時空白」：新增人員時這一格是空的（例：顯示「請選擇性別」），要自己選，不會自動帶第一個選項。只有狀態預設「在職」。
  • 實線箭頭：直接管理或直接查表；虛線箭頭：拿人員資料來用（篩選、檢查、匯出）。

classDiagram
  class Person["人員（一筆資料）"] {
    代碼（id）：系統自動給，例 M-001
    姓名（name）：文字，必填
    性別（gender）：男／女，必填，新增時空白
    生日（birthDate）：日期，必填
    證件類別（idType）：身分證／居留證／護照，必填，新增時空白
    證號（nationalId）：必填，格式看證件類別
    電話（phone）：必填，手機或市話都收
    電子郵件（email）：選填，填了就要格式正確
    居住縣市（residenceCounty）：必填
    居住鄉鎮區（residenceTownship）：必填
    居住地址（residenceAddress）：必填
    編組（groupName）：6 組選 1，必填，新增時空白
    職務（positionCode）：必填，新增時空白
    資格（qualifications）：4 種證照，可複選，選填
    狀態（status）：在職／停用，必填，預設「在職」
    備註（note）：選填
    更新日期（updatedAt）：系統自動寫，不能改
  }
  class Position["職務對照表"] {
    <<固定選項>>
    主任（director）：列表排第 1
    副主任（deputy）：列表排第 2
    組長（leader）：列表排第 3
    組員（member）：列表排第 4
  }

    全部人員清單（records）

④ 狀態圖：明細頁的三種模式

這張圖在說什麼：明細頁只有一頁，但有檢視、編輯、新增三種模式；按不同的鈕，會換到不同的模式。回到列表頁時，原本的篩選和頁碼都還在。

怎麼看
  • 每個圓角框是一種模式（畫面當下的樣子）；黑色圓點是起點；深灰色框是補充說明。
  • 箭頭是「按了什麼，就換到哪個模式」，箭頭上的字就是你按的鈕或發生的事。
  • 繞回自己的箭頭：檢查沒過，欄位下方出現紅字，留在原本的模式讓你改。

⑤ 流程圖：查詢與網址同步

這張圖在說什麼：你改查詢條件，清單馬上跟著變，條件也會寫進網址；所以把網址傳給同事，他打開看到的結果跟你一樣。

怎麼看
  • 最上面一排是參與的角色；從上往下是時間順序，圓圈數字是第幾步。
  • 實線箭頭：去做一件事，或請對方做事；虛線箭頭：對方回覆結果。
  • 深灰色長條：補充說明，不是一個步驟。
